# 知识落地检验体系

> 这套体系回答一个问题：**怎么证明你不是「看懂了」，而是「能改能跑」。**  
> 判据统一为：**在动手项目里加一个组件 / 改一处机制，跑出可观察的差异，并说得出为什么。**  
> 学什么、按什么顺序学 → [`../README.md`](../README.md)；机制细节 → 各 `*-learning-guide.md`。

---

## 1. 为什么要另立一套检验

学习指南里的「过关标准」大多是**口述题**（能不能讲清楚）。口述能过、动手过不了，是自学最常见的假通过。本目录把每条知识点绑到一个**可执行的最小工程改动**上：

```text
读文档  →  改代码（加一个组件）  →  跑命令  →  产物出现预期差异  →  说清因果
                                        ↑
                              这一步过不了 = 没学会
```

**核心约束**：每条检验都必须有「机器能判定的通过标准」（测试通过、IR 出现/消失某条 op、报错信息符合预期、数值一致），不接受「我觉得懂了」。

---

## 2. 分级定义

| 级别 | 名称 | 你要做什么 | 说明 |
|------|------|-----------|------|
| **L0** | 复现 | 跑通既有脚本，读懂产物 | 门槛，不算掌握 |
| **L1** | 改一处 | 改一个参数/规则，**先预测再验证** | 证明你知道因果方向 |
| **L2** | 加组件 | 新增一个 op / pass / pattern / 策略，并补测试 | **主判据**，这一级过了才算掌握 |
| **L3** | 打通 | 跨层或端到端，涉及类型转换、真实后端、多卡 | 加深项，非入门必需 |

**入门线**：每个工具至少完成全部 L0 + 一半以上 L1 + **至少两条 L2**。  
L3 可按兴趣与资源条件选做。

## 3. 资源标签

每条检验都标了运行条件，方便你判断哪些必须申请机器：

| 标签 | 含义 |
|------|------|
| `本地` | 普通开发机 CPU 即可，无额外依赖 |
| `本地+工具链` | 需装 LLVM/MLIR（conda）、TVM、ONNX Runtime 或 CUDA Toolkit；**不需要 GPU 卡** |
| `单卡GPU` | 需要一块可用的 NVIDIA GPU（跑 kernel / CUDA EP / IREE CUDA 后端） |
| `多卡GPU` | 需要同机 ≥2 卡（数据并行、显存实测、通信原语） |
| `多机多卡` | 需要集群与高速互联（跨机并行、NCCL 拓扑） |

**注意**：CUDA fatbin 那一轨里，`nvcc` + `cuobjdump` 属于 `本地+工具链`——只编译不执行 device 代码，**不需要真卡**。真正需要卡的是「把 kernel 跑起来」和「多卡通信」。

## 4. 每条检验的统一写法

各文档里的条目都长这样，读的时候按这几栏对：

```markdown
### L2-XXX-04｜<一句话任务名>

- **检验什么**：这条通过 = 你真的掌握了「<具体知识点>」
- **前置**：需要先完成哪条 / 需要什么环境
- **资源**：本地 / 本地+工具链 / 单卡GPU / ...
- **预计耗时**：0.5h / 2h / 半天

**任务**：要新增或修改什么（具体到文件与函数）

**先预测再动手**：写下你认为会发生什么（这一步不能跳）

**验收命令**：可直接复制执行的命令

**通过标准**：机器可判定的条件（测试绿、IR 里出现/消失什么、报错文案）

**常见失败 → 说明你哪里没懂**：把典型错误映射回知识盲点
```

**「先预测再动手」为什么是硬性的**：改完再解释，人会自动为既成结果编理由；先写预测，才能暴露真实的心智模型。预测错不扣分，**预测错但没发现自己错了**才是问题。

## 6. 记录与申请

### 6.1 怎么记录（建议）

每完成一条，在 `docs/notes/` 里追加或新建一条短记录即可，重点写三样：

1. **预测 vs 实际**（不一致的地方最值钱）
2. **卡了多久、卡在哪一步**
3. **最终验收命令与输出片段**

这批记录就是你「学习过程可追溯」的直接证据。

### 6.2 申请机器时可以直接发的话术

> 老师您好。我在自学 AI 编译栈（MLIR / IREE / TVM / LLVM），前面的编译期内容都在本地 CPU 上完成了（编译器 Pass、dialect 扩展、图划分实验）。  
> 接下来有三类实验必须在真实硬件上做：  
> ① **单卡 GPU**：验证 IREE / TVM 生成的 kernel 在目标架构上数值正确且有性能差异（对比不同 schedule / 不同 target）；  
> ② **多卡**：DDP 与 FSDP 的显存占用与吞吐实测，用来印证显存构成的理论账；  
> ③ **多机（如条件允许）**：跨机通信开销对并行策略选择的影响。  
> 需求不大：①②各需数小时机时，单卡或同机 2～4 卡即可，CUDA 12.x 环境。产出会是可复现的脚本与实验记录，我会整理成笔记提交。

### 6.3 没有机器时怎么办（不阻塞）

标了 `单卡GPU` 以上的条目，都在各文档里给了**降级替代方案**（例如：只编译不运行、用 `--compile-to` 看 IR、用模拟计数代替真实 profiling）。  
**降级版本仍可完成 L0–L2**，只有 L3 的「性能与硬件行为」类结论必须真机。
